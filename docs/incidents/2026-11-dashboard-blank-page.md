# 網站空白打不開事件(2026-11)

## 發生什麼事

合併完 AI 問答功能的幾個小修正(導覽列顏色、聊天泡泡配色)後,使用者回報網站整個打不開——瀏覽器只顯示背景色跟(有時候)分頁標題,完全沒有畫面內容。重新整理多次都一樣,換成 Wi-Fi 也一樣。

## 排查過程

1. **檢查 Render Logs**:看到 `TimeoutError: JavaScript did not respond within 1.0 s`(NiceGUI 內部等待瀏覽器端 JS 回應逾時)跟一筆 `'Session is disconnected'`,但同一段 log 也看得到 `Your service is live`、`Available at your primary URL` 這種正常部署成功的訊息,時間點對不太上使用者實際重試的當下。
2. **排除 Supabase 用量問題**:上次(見 `2026-10-supabase-quota-overage.md`)就是因為背景迴圈把 Supabase 額度打爆,這次第一時間懷疑是不是重蹈覆轍,但使用者確認不是這個原因。
3. **完整重現測試**:用 `git worktree` 把 `main` 分支目前實際部署的那個 commit 整個獨立簽出,**全新建立 venv、全新 `pip install`**(模擬 Render 重新部署會抓到的最新套件版本,而不是沿用本機舊的安裝),重新跑一次 `python app.py`,確認:
   - `/ask`、`/forecast` 頁面都正常回應 200,HTML 內容完整(標題、文字都在,不是空的)
   - 其餘頁面在這個排查環境裡連不到真正的 Supabase(測試用假網址,被這個環境的網路代理擋掉),但那是排查環境本身的限制,不代表程式碼有問題
   - **結論:目前部署的程式碼本身沒有問題**,找不到會導致整頁空白的邏輯錯誤
4. **請使用者手動重新部署**:Render 後台 → Deploys → Manual Deploy → Deploy latest commit(不改任何程式碼,純粹重新開機一次)→ **網站立刻恢復正常**。

## 根本原因

程式碼本身沒問題(有完整重現測試佐證),研判是 **Render 服務實例本身卡住**(連線或記憶體狀態卡死之類),免費/入門方案偶爾會發生,跟這次合併的程式碼改動無關——重新部署的本質就是把容器重開一次,問題隨著重開消失,進一步印證並非程式邏輯造成。

## 學到的教訓

- **網站打不開,且最近有改過程式碼時,不要急著假設是自己的程式碼壞了**——先做一次「完整重現測試」(用乾淨環境重新安裝、重新跑,而不是只看本機舊的測試結果)比較準,能在幾分鐘內排除或確認是不是程式碼的問題,不用靠猜。
- **分不清是程式碼問題還是服務本身卡住時,先試「手動重新部署」**(不改任何東西,純粹重開機)——這個動作成本低、風險低,很多「莫名其妙打不開」的狀況靠這個就解決了,比深入除錯更快有效率。
- **log 時間戳記要對齊實際重試的當下**:這次一開始看的 log 是20幾分鐘前的舊紀錄,容易誤判成「現在還在發生同一個錯誤」,之後排查要確認時間點是不是真的對應到當下那次嘗試。

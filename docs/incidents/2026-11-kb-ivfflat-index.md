# /ask 知識庫搜尋「明明有答案卻找不到」事件(2026-11)

## 發生什麼事

PR #198 為 `/ask` 加上 RAG 工具 `search_manual`:把 17 筆 FAQ 轉成向量存進
Supabase 的 `aqua_kb` 表,使用者問操作類問題時,AI 用 `match_aqua_kb()` 這支
資料庫函式找出最相近的幾筆 FAQ 當依據。上線後(2026-11-17)的實機驗證
(PR #199)問了涵蓋各個 FAQ 主題的問題,結果都正常。

同一天重新跑完 `tools/build_kb_embeddings.py` 之後,改用**換句話說**的問題直接
呼叫 `match_aqua_kb(match_count => 5)`,發現回傳筆數不穩定,而且有些問題明明
有對應的 FAQ 卻查不到:

| 問題 | 資料庫裡對應的 FAQ | 要 5 筆,實際回傳 |
|---|---|---|
| 怎麼重設 Wi-Fi | 如何重新設定 Wi-Fi 或 MQTT 連線資訊 | 5 筆(正常) |
| 螢幕沒有顯示怎麼辦 | OLED 螢幕沒有畫面或顯示異常 | **1 筆** |
| 裝置多久傳一次資料 | 裝置多久上傳一次資料 | **0 筆** |
| 登入被鎖住 | 後台登入失敗太多次被鎖定怎麼辦 | **0 筆** |

影響範圍:使用者問到這類說法時,`search_manual` 查不到任何 FAQ,AI 只能回答
「查無資料」或沒有依據的說法。資料沒有損壞,只是搜尋漏找。

## 根因

`sql/11_knowledge_base.sql` 替 `aqua_kb.embedding` 建了一個
`ivfflat (lists = 10)` 向量索引。ivfflat 是「近似」搜尋:建立時把向量分成
`lists` 個群組,查詢時預設只搜尋其中 **1 個**群組(`ivfflat.probes = 1`),
所以真正最相近的那一筆如果落在沒被搜尋的群組,就整個找不到。

這個索引是為幾千筆以上的資料設計的。這張表只有 17 筆,分成 10 個群組,大多數
群組是空的或只有 1 筆,查詢很容易剛好搜尋到空群組,結果就是回傳 0 或 1 筆。

加重因素(推測,未另外驗證):migration 是在表還是空的時候建立索引,而
ivfflat 的群組中心是在**建立索引當下**用現有資料計算的,所以群組中心沒有
真正反映後來才寫入的 FAQ 向量。

**為什麼先前的驗證沒抓到**(推測):PR #199 的驗證問的是跟 FAQ 標題很接近的
問題,恰好都落在有被搜尋到的群組;而且驗證看的是「AI 有沒有答出來」,沒有直接
檢查資料庫函式**回傳了幾筆**。

## 怎麼解決的

1. 在 Supabase SQL Editor 執行一次
   `drop index if exists public.aqua_kb_embedding_idx;`。資料表和資料都不受影響。
2. 用同樣的問題再測一次 `match_aqua_kb()`,6 個問題全部回傳 5 筆,而且第一名
   都是對的 FAQ。這也確認了根因就是索引。
3. 修改 `sql/11_knowledge_base.sql`(PR #201):不再建立索引,改成「如果存在就
   刪除」。這樣日後重新執行這份 migration(它設計成可重複執行)也不會把索引
   建回來,而且在已經跑過舊版的資料庫上重跑也是安全的。

17 筆資料用一般的逐筆比對(sequential scan)就是精確的,而且是瞬間完成,不需要
索引。

## 學到的教訓(供下次專案參考)

- **小資料表不要建近似搜尋(ANN)索引。** 幾十筆資料逐筆比對又快又準;ivfflat 這
  類索引要幾百到幾千筆以上才有意義,而且要調 `lists` 與 `ivfflat.probes`。真的
  要用,也要在資料寫入**之後**才建立索引,群組中心才有代表性。
- **驗證檢索功能要用「換句話說」的問題,而且直接檢查回傳筆數。** 只看「AI 有沒有
  答出來」會漏掉這種「搜尋漏找」的問題,因為 AI 常常能在查不到時用別的方式
  交差。這次是繞過 AI,直接呼叫 `match_aqua_kb()` 並斷言「回傳 5 筆、第一名是
  對的」才發現的。
- **資料庫裡手動修好之後,一定要同步修 migration 檔案。** 這次線上資料庫已經刪掉
  索引,但檔案裡的 `create index` 還在,任何人日後重跑檔案都會把問題帶回來。
  migration 檔要能代表資料庫的「正確最終狀態」,而不是只記錄第一次怎麼建的。
- **這類資料庫修正沒辦法從開發機自動執行**(沒有 DDL 的執行路徑),要請使用者
  到 Supabase SQL Editor 手動貼一行指令,所以交付時要把「要跑哪一行」寫清楚。
